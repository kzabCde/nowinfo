# NowInfo — แผนโครงการ

> อัปเดต v0.2 ตามทิศทางล่าสุด: ใช้ localStorage เป็นที่เก็บข้อมูลผู้ใช้และแคชข่าวก่อน ไม่เพิ่มฐานข้อมูลหรือระบบบัญชี แดชบอร์ดโลกและ Dark/Light พร้อมใช้งาน รายละเอียดปัจจุบันอยู่ใน DASHBOARD-v0.2.md ข้อเสนอฐานข้อมูลด้านล่างเป็นแนวทางอนาคตเท่านั้น ไม่ใช่งาน Phase 2 ที่จะดำเนินการโดยอัตโนมัติ.

## 1. แนวคิดและเป้าหมาย

NowInfo คือศูนย์รวมข่าวที่ช่วยตอบ 3 คำถาม: เกิดอะไรขึ้น → เกี่ยวข้องกับใคร → ควรติดตามอะไรต่อ มุ่งให้ผู้อ่านภาษาไทยเข้าใจความเชื่อมโยงของเหตุการณ์ระดับโลกกับชีวิต เศรษฐกิจ เทคโนโลยี พลังงาน สิ่งแวดล้อม และประเทศไทย

กลุ่มผู้ใช้เริ่มต้น: ผู้ติดตามสถานการณ์โลก นักศึกษา คนทำงาน และผู้ประกอบการที่ต้องการเปิดอ่านข่าวจากหลายหมวดในที่เดียว เป้าหมายคือให้พบข่าวและต้นทางได้ภายใน 3 คลิก ไม่กำหนดให้สมัครสมาชิกก่อนอ่าน

## 2. โครงสร้างผลิตภัณฑ์

| พื้นที่ | รุ่นแรก v0.1 ที่ทำแล้ว | ระยะถัดไป |
|---|---|---|
| ภาพรวมข่าว | ฟีด RSS จริง ค้นหาหัวข่าว/แหล่งข่าว/หมวด เรียงตามเวลา | สรุปประจำวันและจัดลำดับตามความเกี่ยวข้อง |
| หมวดหมู่ | โลก เศรษฐกิจ เทคโนโลยี พลังงาน สิ่งแวดล้อม | สุขภาพ ความมั่นคง อาหาร และข้อมูลประเทศไทย |
| บริบทข่าว | คำถามทั่วไปตามหมวดและลิงก์ต้นฉบับ | สรุปไทยแบบอ้างหลักฐาน วิเคราะห์ผลกระทบเป็นรายเหตุการณ์ |
| บันทึกข่าว | เก็บในเบราว์เซอร์ สูงสุด 100 ข่าว | บัญชีผู้ใช้และซิงก์ข้ามอุปกรณ์ |
| แหล่งข้อมูล | แสดงสถานะรายฟีดและเวลาตรวจสอบ | ประวัติความพร้อมใช้งานและรายงานข้อผิดพลาด |
| ภาษา | เมนูไทย/อังกฤษ หัวข่าวภาษาต้นฉบับ | คำแปลข่าวแบบระบุว่าเป็นคำแปล |

สิ่งที่ยังไม่ใช่ความสามารถรุ่นแรก: AI สรุปข่าว, วิเคราะห์ผลกระทบรายเหตุการณ์, คะแนนความเสี่ยง, แผนที่เหตุการณ์, บัญชีผู้ใช้, push notification, ข่าวทุกประเทศ, การแปลต้นฉบับ และประวัติถาวร

## 3. จุดเด่นที่ควรพัฒนาต่อ

1. **Event Hub:** รวมบทความหลายสำนักที่กล่าวถึงเหตุการณ์เดียวกัน แสดง timeline อัปเดตและข้อเท็จจริงที่เปลี่ยน
2. **Impact Lens:** อธิบายเส้นทางผลกระทบ เช่น การเปลี่ยนนโยบายการค้า → ต้นทุนสินค้านำเข้า → ภาคธุรกิจที่เกี่ยวข้อง โดยแต่ละเส้นเชื่อมต้องมีหลักฐานหรือระบุว่าเป็นสมมติฐาน
3. **Thailand Lens:** สรุปว่าเรื่องนี้เกี่ยวกับไทยผ่านช่องทางใด พร้อมตัวชี้วัดที่ควรติดตาม ไม่สรุปว่าทุกข่าวกระทบไทยเสมอ
4. **Daily Brief:** 5–10 เหตุการณ์ประจำวัน พร้อมแหล่งข่าวและสิ่งที่ยังไม่ทราบ
5. **Source Comparison:** แสดงว่าแต่ละสำนักรายงานตรงกันหรือต่างกันในข้อใด แยกมุมมองจากข้อเท็จจริง

## 4. สถาปัตยกรรมรุ่นแรก

- Next.js App Router + TypeScript + React; CSS responsive; Lucide icons
- `GET /api/news`: ดึง RSS แบบขนานจาก URL ที่กำหนดไว้เท่านั้น timeout 8.5 วินาทีต่อฟีด ขนาดสูงสุด 2 MB
- `fast-xml-parser`: ตรวจ XML ปฏิเสธ DTD/entity declarations แปลงเป็นข้อความธรรมดา รับเฉพาะลิงก์ HTTP/HTTPS
- รวมข่าวซ้ำด้วย canonical URL และ normalized headline ก่อนเรียงตาม publication time
- ถ้าไม่ระบุเวลา/เวลาผิด/เวลาไกลในอนาคต แสดงไม่ระบุเวลา ไม่ตั้งเวลาใหม่ทับ
- Vercel CDN: cache 300 วินาที + stale-while-revalidate 60 วินาที; client ขออัปเดตทุก 5 นาทีขณะมองเห็นหน้า
- ไม่มี cron, ฐานข้อมูล, secret หรือ AI API ที่ต้องตั้งค่าก่อนใช้รุ่นแรก
- หากฟีดบางตัวล้มเหลว ตัวอื่นยังแสดงได้; ถ้าทั้งหมดล้มเหลว API ตอบ 503 และหน้าเว็บแจ้งเตือน
- การกด refresh อาจยังได้ cache ภายในช่วง 5 นาที ไม่ได้บังคับให้ upstream ตอบข่าวใหม่

โครงสร้างไฟล์: `app/` หน้าและ API, `components/` ส่วนติดต่อผู้ใช้, `lib/` RSS/types/content, `tests/` parser และ error cases, `docs/` แผนและวิธี deploy

## 5. แหล่งข้อมูลและนโยบายเนื้อหา

แหล่งเริ่มต้น: BBC World, Business, Technology, Science & Environment; Federal Reserve All Press Releases; UN News รวม 6 ฟีดจาก 3 ผู้เผยแพร่ ขอบเขตเริ่มต้นใช้ภาษาอังกฤษเป็นหลักและมีข้อจำกัดด้านความหลากหลาย

แสดงหัวข่าว แหล่งเผยแพร่ เวลา และลิงก์เท่านั้น ไม่คัดลอกบทความเต็ม ไม่ใส่ภาพข่าวโดยไม่มีสิทธิ์ ไม่กล่าวอ้างว่าเป็นพันธมิตรกับเจ้าของแหล่งข่าว

รายการแหล่งข้อมูลและเงื่อนไขต้องได้รับการตรวจสอบก่อนเปิดฟีเจอร์เชิงพาณิชย์หรือเพิ่มแหล่งใหม่ RSS ไม่ได้หมายความว่าอนุญาตให้ใช้ทุกอย่างโดยไร้ข้อจำกัด

อ้างอิงการให้บริการ RSS:
- BBC: https://support.bbc.co.uk/platform/feeds/NewsFeeds.htm
- Federal Reserve: https://www.federalreserve.gov/feeds/feeds.htm
- United Nations: https://www.un.org/en/ga/rss/index.shtml (แนวทาง RSS ของ UN; endpoint ข่าวที่ใช้ระบุใน lib/news.mjs)

## 6. ข้อมูลสำหรับระยะที่มีฐานข้อมูล

| ตาราง | ข้อมูลหลัก |
|---|---|
| sources | URL, publisher, license notes, enabled, last success |
| articles | source ID, canonical URL (unique), title, published_at, fetched_at, content hash |
| events | event title, region, first_seen, last_seen, review status |
| event_articles | event ID, article ID, relevance, grouping version |
| analyses | event ID, language, summary, observed facts, hypotheses, evidence links, model/prompt version |
| impact_links | event ID, affected sector/region, mechanism, evidence, uncertainty |
| ingest_runs | start/end, source counts, article counts, failures, latency |
| profiles / bookmarks | user ID, preferences, article/event ID, created_at |

เริ่มจาก managed Postgres เมื่อจำเป็นต้องเก็บประวัติและซิงก์บัญชี เลือกบริการและค่าใช้จ่ายในขั้นนั้น ข้อมูลสาธารณะแยกจากข้อมูลส่วนบุคคล และทดสอบสิทธิ์อ่านเขียนข้ามบัญชีก่อนเปิดใช้

## 7. Roadmap และเกณฑ์ส่งมอบ

| ระยะ | งาน | เกณฑ์ยอมรับ |
|---|---|---|
| Phase 1 — Reader MVP | ฟีดจริง ค้นหา กรอง บันทึก แหล่งข่าว เมนูสองภาษา deploy | build ผ่าน, URL จริงเปิดได้, API รายงานสถานะจริง, ไม่มีข่าวจำลอง |
| Phase 2 — Reliable ingestion | เก็บประวัติ ingestion log, retry/backoff, source health, แหล่งข่าวหลายภูมิภาค | ingest ซ้ำไม่สร้างข้อมูลซ้ำ, restore ข้อมูลได้, source failure ไม่หยุดทั้งระบบ |
| Phase 3 — Event intelligence | รวมเหตุการณ์ สรุปไทย หลักฐานรายประโยค timeline | ชุดทดสอบที่ผู้ตรวจทำไว้, ทุกข้อสรุปย้อนถึงแหล่งได้, จัดการแหล่งที่ขัดแย้งกัน |
| Phase 4 — Thailand & personal | Thailand lens, topic follows, account sync, daily brief | กำหนดสิทธิ์บัญชีผ่าน, เลือกรับ/ยกเลิกแจ้งเตือนได้, สรุปแยกข้อเท็จจริง/สมมติฐาน |

ประมาณการพัฒนาเพิ่มเติมสำหรับผู้พัฒนา 1 คน: Phase 2 ราว 1–2 สัปดาห์, Phase 3 ราว 2–4 สัปดาห์, Phase 4 ราว 1–2 สัปดาห์ ขึ้นกับสิทธิ์แหล่งข้อมูลและความเข้มงวดในการตรวจบทวิเคราะห์ เป็นแผนประมาณการ ไม่ใช่กำหนดส่งที่รับประกัน

## 8. แนวทาง AI ในอนาคต

เริ่มแบบ human-reviewed ก่อนเผยแพร่อัตโนมัติ อินพุตคือข่าวจากแหล่งที่กำหนดไว้ ไม่รับคำสั่งในเนื้อหาข่าวเป็นคำสั่งระบบ ผลลัพธ์มี schema: facts, summary_th, affected_regions, affected_sectors, possible_impacts, watch_next, uncertainties, source_urls

ทุก fact ต้องมี evidence URL; possible impact ต้องระบุเงื่อนไขและความไม่แน่นอน ไม่มีคะแนนความเชื่อมั่นเป็นเปอร์เซ็นต์หากไม่ได้ปรับเทียบกับชุดประเมิน บันทึก model, prompt version, generated_at และต้นทุนต่อผลลัพธ์ มี fallback เป็นข่าวต้นฉบับเมื่อ AI ล้มเหลว

## 9. ค่าใช้จ่ายและการดูแล

รุ่นแรกไม่มีบริการ API แบบเสียเงินที่เพิ่มเข้ามา ใช้งานทรัพยากรตามแพ็กเกจ Vercel ของผู้ใช้ ไม่รับประกันค่าใช้จ่ายเป็นศูนย์ในทุกปริมาณใช้งาน ตรวจข้อกำหนดแพ็กเกจและแหล่งข่าวก่อนเปิดเชิงพาณิชย์ รุ่นถัดไปควรกำหนดงบฐานข้อมูลและ AI รายเดือนก่อนเปิดใช้จริง

ตัวชี้วัดที่ควรติดตาม: สัดส่วนฟีดที่อ่านได้, เวลาจาก publication ถึง ingestion, ข่าวซ้ำที่หลุด, อัตราลิงก์เสีย, latency API, ความถูกต้องของการจัดหมวด, ความถูกต้องของสรุปไทยจากผู้ตรวจ และการเปิดอ่านต้นทาง

ไม่มีการติดตั้ง analytics ติดตามผู้ใช้ในรุ่นแรก
